# Scientific plotting library decision

## Decision

Use the exact `plotly.js-strict-dist-min@4.1.1` distribution as the workspace renderer. It replaces the initial Cartesian-only bundle to add pie/doughnut traces while keeping all twelve supported families under the existing nonce-only script CSP. Numerical extraction, statistics, transforms, alignment, gridding and exports remain under `src/parser/plot/`, shared with MCP. Plotly receives finished datasets, including category weights/shares, histogram counts and box quartiles. It does not define the numerical backend.

| Candidate | Required families | CSP/offline considerations | Decision |
| --- | --- | --- | --- |
| Plotly Cartesian | Direct support for Cartesian line/scatter, bars, boxes, heatmaps and contours; host supplies histogram bins/box statistics. No pie traces. | Local prebuilt distribution; initial seven-family CSP/export regression passed. | Initial choice; replaced for circular charts. |
| Plotly strict | Includes scatter/bar/box/heatmap/contour/pie; step/area/bubble are explicit scatter styles. Host computes category aggregation/shares. | Exact local prebuilt bundle, MIT attribution, nonce-only scripts; twelve-family regression has no CSP violation or HTTP request. Larger than Cartesian. | Selected for the expanded picker. |
| Apache ECharts | Strong line/scatter/bar/box/heatmap coverage; contour plots need a separate adapter/custom series | Offline bundling and accessibility features are available; SVG/Canvas renderers offer export choices. The custom contour and its masking/export/accessibility rules would be extension-owned. | Not selected; greater contour-adapter scope. |
| Vega / Vega-Lite | Declarative scientific plotting, but contours/interpolation need additional dataflow decisions | Strict-CSP deployments require the expression interpreter rather than the default expression code-generation path; would introduce another transformation grammar beside the shared host core. | Not selected for this graphical builder. |

References: [Plotly partial-bundle trace coverage](https://github.com/plotly/plotly.js/blob/master/dist/README.md), [Plotly static image export](https://plotly.com/javascript/static-image-export/), [ECharts accessibility](https://echarts.apache.org/handbook/en/best-practices/aria/), [Vega expression interpreter](https://github.com/vega/vega/tree/main/packages/vega-interpreter). The comparison is architectural; it is not a head-to-head benchmark of all three libraries.

## Packaging and CSP

`esbuild.js` copies the strict bundle and its MIT license into `media/plotly/`, and builds `media/plots.js` plus `dist/plotWorker.js`. The plotting library is not imported by the host or numerical core. The mesh webview reuses the workspace adapter and loads the local Plotly script **only on first opening Plots**, under the preview's nonce; the standalone workspace loads it directly. There is no `unsafe-eval` CSP allowance, external script source or network dependency for the supported charts. Plotly inserts styles dynamically, so the workspace retains `style-src 'unsafe-inline'`; PNG generation uses `img-src blob:` as well as `data:`. That is an image-export allowance, not a script-CSP relaxation.

The shipped minified plotting asset is **5,158,139 bytes** (the initial Cartesian asset was 1,500,041 bytes). The expanded increment's packaged extension measured **30.95 MB** in this environment, versus 29.89 MB for the earlier integrated increment; that figure includes all existing renderer/WASM assets, not just plotting. Attribution is shipped as `media/plotly/LICENSE`. The prebuilt strict bundle includes unused map/WebGL families: the recipe whitelist and adapter expose only scatter/bar/box/heatmap/contour/pie traces. Static inspection finds dormant map-worker `globalThis.eval` and a global-object fallback `new Function`; neither runs in the supported chart paths, and the CSP does **not** authorize them. The twelve-family offline/export check observed no page error, CSP violation or HTTP request. This is a scoped runtime audit, not a claim that every trace in the full upstream bundle can run offline under this CSP.

The chart's default palette and chrome use VS Code tokens; explicit series colors remain user data styling. A labelled visual SVG picker, native configuration controls, visible focus, keyboard zoom/resize buttons and accessible sample tables (including bubble weights/circular shares) provide alternatives to pointer-only chart gestures. Plotly itself is not presented as fully keyboard-accessible.

## Directory-result receipt contract

`src/problemtype/runResultInventory.ts` exports `freezeExecutionResult(source, signal)` for an owning receipt writer or explicit importer. It reads the complete source closure twice and refuses changes/missing files, returning the entrypoint as `role: "result"` with its byte `revision` and directory `inventoryRevision`, plus `role: "result-companion"` revisions for dependencies. Store those artifacts in the existing `.kkss-execution.json` while freezing the owning execution's terminal receipt. MCP receipt collection uses the same helper for explicitly recorded directory result entrypoints; this adds no solver output-process adapter, automatic folder adoption, run manager or retrospective legacy ownership resolution. Terminal status polling preserves the frozen artifacts.

The version-1 `inventoryRevision` is SHA-256 over the UTF-8 JSON serialization of `[1, meshExtension, entrypointBasename, timelineKind, framePairs, fileTuples, directoryPaths]`. `timelineKind` is `single`, `files` or `inFile` from shared discovery; `framePairs` are its ordered `[label, frameIndex]` pairs. `fileTuples` contain `[relativePath, byteLength, sha256Revision]` for every dependency and the selected entrypoint, relative to its parent directory with `/` separators, sorted by their JSON serialization using lexical code-unit ordering. `directoryPaths` are relative `/` paths sorted lexically, including empty selected directories. Absolute paths, timestamps and realpaths do not enter this portable closure. The recipe binding still pins its exact source/realpath identity, so relocating a saved run requires explicit rebinding even when the frozen closure remains valid. The packaged harness's independent fixture writer implements this contract without importing checkout runtime code.

OpenFOAM inventories conservatively include entire `constant`, `system`, numeric-time and `processorN` trees. Each baseline `constant[/region]/polyMesh` must contain `points`, `faces` and `owner` (plain or gzip); moving overlays may be partial. Elmer root filenames share the staging collector's patterns and partition trees are conservative; MFEM includes all matching sibling ranks, not an invented independently owned rank. Linked/non-regular dependencies, changing enumerations, over 50,000 entries or over 20 levels are refused. Hashing unread fields/dictionaries is dependency coverage, not a claim that the reader interprets their semantics. Individual file hashes alone cannot prove an unchanged directory closure, because a removed dependency would disappear from today's enumeration; directory-backed results therefore require the frozen `inventoryRevision` too. Do not add it to an old receipt using current bytes as evidence of a past run.

## Persistent extraction cache

`src/parser/plot/persistentCache.ts` is an opt-in, bounded on-disk cache for disk-backed extractions: mesh tables, probe profiles, current-frame regional quantities and unowned histories. Enable it with the `kratos.plots.persistentCache` setting (global storage), the `cacheDir` argument of `plot_dataset`, or the `KRATOS_PLOT_CACHE_DIR` environment variable for headless callers. Default is off.

- **Key.** SHA-256 of the schema version, `plotSourceIdentity(path).revision` (streamed content hashes of the root file, every companion, the selected rank and the timeline steps), and the source settings without its `run` binding. Any changed, added or missing file, step or setting is therefore a different key; there is no mtime shortcut.
- **Verified both sides.** The identity is computed before the extraction and again before the entry is stored; if the files changed in between, nothing is stored.
- **Stat shortcut.** A lookup first compares a manifest of every file's size, mtime, ctime, inode and device (plus the directory listing) with the disk and, when all are identical and each file was already 2 s old when the manifest was written, reuses the stored content revision without hashing (`statFastPath`, default on; `statSettleMs`). ctime cannot be restored by a writer the way mtime can, so an in-place rewrite misses; a file written inside the settle window, an added sibling file or a directory-case source is hashed as before, and a store always rehashes. Measured on the benchmark below it is about 30x faster than a hashed hit.
- **Never cached.** Live-mesh snapshots (`models`), tables (already content-cached in memory), inline sources and sources bound to a verified run, which keep their own verification (a cache hit would skip the before/after receipt check, so this is a decision, not a gap). The retained fixed snapshots used by profile following are a separate in-memory cache: a persistent hit never fills it, and a retained miss still fails rather than rereading disk (`plotPersistentCache.test.ts`).
- **Bounds.** 256 MiB and 512 entries by default, evicting the least recently used by access time; other-schema files and stale temp files are swept; a corrupt entry is deleted and treated as a miss; a table holding non-finite numbers is not stored because JSON cannot reproduce it.
- **Cost, measured on the 3.6 KB `example/VTK` series (Node 22, one run, not a budget):** identity hashing 15 ms, uncached history 28 ms, hit 9 ms. A hit still hashes every companion, so on large inputs its cost scales with the bytes of the source and companions rather than with the parse; a million-row or multi-gigabyte benchmark has not been run and no large-data budget is claimed.

## Measured budgets (Node level)

`npm run bench:plot` (`scripts/bench/plot-budget.mjs`; verdict logic in `plotBudgetStats.mjs`, unit-tested in `benchPlotBudget.test.ts`; deliberately not part of `npm test` because timing on shared CI is flaky) measures the Node main thread, which is what an extension host is, and a worker. Table cases run in a fresh process per repetition so the RSS high-water mark is that case's own. The table below is the **pre-fix** measurement (medians of 3 runs on `linux x64 Intel(R) Xeon(R) Processor @ 2.10GHz x4, node v22.22.0`), kept because it records what the two failing budgets actually were:

| Case | Result |
|---|---|
| 1,000,000-row, 8-column CSV (67.9 MiB), plot in-process | 10518 ms wall, 5.9 ms max stall, 1527 MB peak RSS above an empty process |
| same plot through the plot worker | 17089 ms wall, 3137.3 ms max stall, 1698 MB peak RSS above an empty process |
| history extraction, 12 steps x 60000 nodes, cold | 2211 ms |
| same, persistent hit with full content hashing | 54.9 ms |
| same, persistent hit via the stat shortcut | 1.6 ms |
| worker cancellation (abort to settle) | 2.0 ms |

Verdicts against the default budgets (worker max stall 50 ms, table peak RSS 12x the file, cancellation 500 ms, stat shortcut at least 1.5x faster) were, in that run: cancellation **pass**, stat shortcut **pass**, worker stall **fail**, table memory **fail**. The two failures were real findings, not threshold artifacts: a million-row plot held about 1.5 GB at peak (about 22x the file; the rows, per-row origins and points were all materialized as JavaScript objects), and returning that dataset from the worker blocked the host for about 3 s while it was structured-cloned, so the worker protected the host during the parse but not during delivery.

Both were fixed by streaming the import into numbers and delivering large arrays in acknowledged chunks (`src/plotChunks.ts`), and the 2026-10-16 run recorded in roadmap item 19 passes all four budgets: peak RSS **10.6x the file** (was 23x) and worker host stall **34 ms** (was about 2 s). No further benchmark run was repeated for the 2026-10-21 packaged-acceptance increment, so no newer timing numbers are claimed here.

Not measured here, and not claimed: the VS Code extension host, Remote-SSH or network filesystems, webview delivery, a packaged VSIX, and the WASM mesh formats' worker lifetime.
