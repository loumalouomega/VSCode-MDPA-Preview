# Scientific plotting library decision

## Decision

Use the exact `plotly.js-strict-dist-min@4.1.1` distribution as the workspace renderer. It replaces the initial Cartesian-only bundle to add pie/doughnut traces while keeping all twelve supported families under the existing nonce-only script CSP. Numerical extraction, statistics, transforms, alignment, gridding and exports remain under `src/parser/plot/`, shared with MCP. Plotly receives finished datasets, including category weights/shares, histogram counts and box quartiles. It does not define the numerical backend.

| Candidate | Required families | CSP/offline considerations | Decision |
| --- | --- | --- | --- |
| Plotly Cartesian | Direct support for Cartesian line/scatter, bars, boxes, heatmaps and contours; host supplies histogram bins/box statistics. No pie traces. | Local prebuilt distribution; initial seven-family CSP/export regression passed. | Initial choice; replaced for circular charts. |
| Plotly strict | Includes scatter/bar/box/heatmap/contour/pie; step/area/bubble are explicit scatter styles. Host computes category aggregation/shares. | Exact local prebuilt bundle, MIT attribution, nonce-only scripts; twelve-family regression has no CSP violation or HTTP request. Larger than Cartesian. | Selected for the expanded picker. |
| Apache ECharts | Strong line/scatter/bar/box/heatmap coverage; contour plots need a separate adapter/custom series | Offline bundling and accessibility features are available; SVG/Canvas renderers offer export choices. The custom contour and its masking/export/accessibility rules would be extension-owned. | Not selected; greater contour-adapter scope. |
| Vega / Vega-Lite | Declarative scientific plotting, but contours/interpolation need additional dataflow decisions | Strict-CSP deployments require the expression interpreter rather than the default expression code-generation path; would introduce another transformation grammar beside the shared host core. | Not selected for this graphical builder. |

References: [Plotly partial-bundle trace coverage](https://github.com/plotly/plotly.js/blob/master/dist/README.md), [Plotly static image export](https://plotly.com/javascript/static-image-export/), [ECharts accessibility](https://echarts.apache.org/handbook/en/best-practices/aria/), [Vega expression interpreter](https://github.com/vega/vega/tree/main/packages/vega-interpreter). The comparison is architectural; it is not a head-to-head benchmark of all three libraries.

## Packaging and CSP

`esbuild.js` copies the strict bundle and its MIT license into `media/plotly/`, and builds `media/plots.js` plus `dist/plotWorker.js`. The plotting library is not imported by the host or numerical core. The mesh webview reuses the workspace adapter and loads the local Plotly script **only on first opening Plots**, under the preview's nonce; the standalone workspace loads it directly. There is no `unsafe-eval` CSP allowance, external script source or network dependency for the supported charts. Plotly inserts styles dynamically, so the workspace retains `style-src 'unsafe-inline'`; PNG generation uses `img-src blob:` as well as `data:`. That is an image-export allowance, not a script-CSP relaxation.

The shipped minified plotting asset is **5,158,139 bytes** (the initial Cartesian asset was 1,500,041 bytes). The expanded increment's packaged extension measured **30.95 MB** in this environment, versus 29.89 MB for the earlier integrated increment; that figure includes all existing renderer/WASM assets, not just plotting. Attribution is shipped as `media/plotly/LICENSE`. The prebuilt strict bundle includes unused map/WebGL families: the recipe whitelist and adapter expose only scatter/bar/box/heatmap/contour/pie traces. Static inspection finds dormant map-worker `globalThis.eval` and a global-object fallback `new Function`; neither runs in the supported chart paths, and the CSP does **not** authorize them. The twelve-family offline/export check observed no page error, CSP violation or HTTP request. This is a scoped runtime audit, not a claim that every trace in the full upstream bundle can run offline under this CSP.

The chart's default palette and chrome use VS Code tokens; explicit series colors remain user data styling. A labelled visual SVG picker, native configuration controls, visible focus, keyboard zoom/resize buttons and accessible sample tables (including bubble weights/circular shares) provide alternatives to pointer-only chart gestures. Plotly itself is not presented as fully keyboard-accessible.

Playwright and code-server remain external test tooling, not extension dependencies.

## Kernel baseline hold

This task intentionally retains the audited **meshio++ 16.27.0** lockfile baseline. A newer published kernel (16.30.0 during initial planning) does not justify bypassing the roadmap's Tier 0 registry/options/reader/writer/transient audit. Upgrade and audit that kernel separately; none of the plotting delivery claims depends on its untested new behavior.

## Remaining acceptance scope

Roadmap item 14 remains open. Run discovery/ownership-aware cross-run navigation, additional analysis-table/FEM relationship/volume/threshold presets, expanded tensor/thermal/geometry conventions, companion-aware caches, larger-scale/remote budgets and a broader packaged save/export/recipe/stale/cancellation matrix are not closed by the current measurements. Session-only fixed-extraction retention for frame following is not a persistent companion-aware cache or a verified run-ownership contract. The guide states these boundaries rather than implying that chart-library adoption or the embedded increment completes the whole task.
