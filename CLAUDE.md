# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run compile        # dev build (includes source maps)
npm run package        # production build (minified, no source maps)
npm run typecheck      # type-check only — never use tsc to emit shipped code
npm test               # compile tests then run with Node's built-in test runner
npm run build:icons    # regenerate src/toolbarIcons.ts from icons/tikz-ui/*.tex (needs pdflatex + pdftocairo)
npm run install-ext    # build + copy into ~/.vscode-server/extensions/ (bash install.sh)
npm run reinstall      # bump patch version, package a .vsix, install via `code --install-extension`, prune stale versions (bash scripts/reinstall-local.sh) — also available as the "Reinstall extension (local/Remote-SSH)" VS Code task
```

**esbuild owns all emit** — `tsc` is only for type-checking and test compilation. Do not run `tsc` to build the extension.

To run a single test file:
```bash
npm run build:tests && node --test out/test/mdpaParser.test.js
```

The documentation site is a **separate, isolated npm package** under `doc/` (its own `package.json`/`package-lock.json`, `"type": "module"`) so VitePress never touches the extension build or the packaged `.vsix`. Run its commands from inside `doc/`:
```bash
cd doc && npm install       # first time only
npm run docs:dev            # local dev server with HMR
npm run docs:build          # production build → doc/.vitepress/dist (fails on dead links)
npm run docs:preview        # serve the built site
```

## Architecture

The extension has two completely separate runtimes that communicate only via `postMessage`:

### Extension host (Node.js, `src/`)
- `extension.ts` — registers two custom editors (`kratos.mdpaPreview` for `.mdpa`, `kratos.vtkPreview` for the mesh formats `.vtk`/`.vtu`/`.vtp`/`.vti`/`.vts`/`.vtr`/`.vtm`/`.stl`/`.obj`/`.ply`) and commands. A shared `postToActive` helper forwards panel-level commands (reset camera, field, etc.) to whichever provider currently has an active panel. The `kratos.mesh.*` commands (open/save/saveAs/export) route through `dispatchMenu` (which calls each provider's `dispatchMenu`) for Command-Palette parity with the in-webview File menu.
- `src/meshExport.ts` — shared host-side File-menu handlers used by both providers: `openMesh` (showOpenDialog → `vscode.openWith` the matching viewType), `saveMesh` (re-serialise to the source's own format and overwrite it, one-time `globalState`-gated overwrite warning), `saveMeshAs`, `exportMesh`, `exportSubModelPart` (slices one SubModelPart out via `extractSubModelPart` and writes it to a chosen format), and `runMenu(msg, getCtx, extContext)` routing a `MenuMessage`. All serialization funnels through `serializeModelToPath`; the webview only posts the command (`menuOpen`/`menuSave`/`menuSaveAs`/`menuExport`/`menuExportPart`). Each provider caches the last parsed model (`lastModel`) and registers a per-panel `activeMenuHandler` so palette commands reach the active preview. (Mesh operations no longer live here — see `src/opHistory.ts` / `src/parser/operations.ts`.)
- `src/opHistory.ts` — host-side **operation history** (undo/redo/partial-revert + JSON recipe I/O) shared by the Edit + Mesh Modification sidebar sections. `OperationHistory` is a **replay-from-base** stack: `setBase(model)` (called on every parse/frame load — so history resets on reparse/frame change), **async** `applyNew(rec)` (truncates the redo tail, records unless the op is a noop), `undo`/`redo`/`clear`/`revertTo(n)`, **async** `current()` = `replayOpsAsync(base, ops[0..cursor))`, `load(records)`, and `state()` for the webview. Prefixes ending in an MMG op are **snapshotted** (`Map<prefixLen, OpApplied>`) so undo/redo of later ops never re-runs the remesher; `current()` replays from the nearest snapshot ≤ cursor (snapshots past the cursor are invalidated on truncation; cleared on `setBase`/`load`/`clear`, so loading a recipe re-runs MMG). Op params are entered in the sidebar (interactive forms) and ride along on the `applyOp` message — the host builds the record with `opRecordFromMessage` (no native prompts). `saveOps`/`loadOps` are the showSaveDialog/showOpenDialog + `fs` recipe writers/readers. Each provider owns one instance; `lastModel` always equals `current().model`, so File ▸ Save/Export serialize the edited mesh. Pure replay/dispatch/JSON live in `src/parser/operations.ts`.
- `src/parser/operations.ts` — pure (no `vscode`/DOM/vtk) operation core: the serializable `OpRecord` union (`linearToQuadratic` | `removeOrphanNodes` | `mergeNodes{tolerance}` | `scale{sx,sy,sz}` | `translate{dx,dy,dz}` | `rotate{axis,angle,cx?,cy?,cz?}` | `deleteSubModelPart{path}` | `remesh{mode,factor?,hsiz?,hmin?,hmax?,hausd?,hgrad?,angleDetection?,nosurf?,noinsert?,noswap?,nomove?,module?}` | `levelset{variable,isovalue?,isosurf?,+tuning}`), `applyOp(model, rec)` (sync ops only — **throws** for the MMG ops), `applyOpAsync`/`replayOpsAsync` (run everything incl. MMG; take `MmgRunOptions {onProgress?, signal?}` — cancellation/worker failure surfaces as a noop outcome with a message, and an aborted signal stops a replay between ops), the swappable **`MmgRunner`** (`configureMmgRunner` — default runs in-process for tests; the extension installs the worker client), `isAsyncOp(op)` (drives the providers' progress UI + history snapshotting), `opRecordFromMessage(msg)` (validates a raw `applyOp` webview message + its sidebar params into an `OpRecord`), `OP_LABELS`, and `serializeOps`/`parseOpsJson` (versioned JSON recipe with unknown-op/param validation → warnings). Node-testable; drives `OperationHistory`. Unit tests: `src/test/operations.test.ts`.
- `src/parser/remesh.ts` — **MMG remeshing** via `@loumalouomega/mmg-wasm` (MMG v5.8.0 as WASM; async, Node-testable, no `vscode`/DOM). `remeshModel(model, params)` — modes `factor` (per-node scalar metric = mean incident-edge length × factor), `hsiz` (`DPARAM_hsiz`), `optimize` (`IPARAM_optim`); tuning `hmin/hmax/hausd/hgrad`, `angleDetection` (≤0 → `IPARAM_angle` off), `nosurf/noinsert/noswap/nomove`. `levelsetModel(model, params)` — nodal field (vector → magnitude, full coverage required) → `h.ls` scalars, `IPARAM_iso`/`isosurf` + `DPARAM_ls`; output regroups into `MMG_Domain_Inside`/`_Outside` + `MMG_Interface`(`_Edges`) blocks. Module auto-detect: tets → `mmg3d` (prisms pass through; tris/quads/edges = boundary), else planar (z ≈ const) → `mmg2d` (2-double coords, z restored) else `mmgs`; hex/pyramid/quadratic/point-only meshes → noop + message. **Ref encoding is how blocks + SubModelParts survive**: each cell gets a dense ref for its (block, sorted SMP-path list) signature; the harvest regroups by ref. Caveats baked in: MMG tags internally-created boundary faces with the adjacent domain cell's ref, so a ref only maps back when the cell family matches (ref 0 / family mismatches are dropped as internal boundary), and level-set refs start at 100 because ls mode rewrites domain refs to MG_MINUS/MG_PLUS (2/3). Node + entity ids are freshly renumbered; SMP node lists = connectivity closure of their cells; fields dropped with a warning; `free(h)` in `finally`; `IPARAM_verbose` −1. `configureMmg(opts)` injects Emscripten overrides once — `extension.ts` passes `{ wasmBinary: readFileSync(__dirname/mmg-core.wasm) }` at activation; plain Node (tests) self-resolves. **Progress**: `remeshModel`/`levelsetModel` take an optional `onProgress(message)` — stage messages plus MMG's own log (Emscripten `print`/`printErr` route through a module-level listener fixed at initialize time; `IPARAM_verbose` 3 when a callback is given, −1 otherwise; banner noise filtered by `progressLine`). Unit tests: `src/test/remesh.test.ts` (run the real WASM).
- `src/mmgWorker.ts` / `src/mmgWorkerClient.ts` — the **MMG worker pair** (no `vscode` imports). The remesher is a synchronous C call, so `extension.ts` registers `runMmgInWorker` via `configureMmgRunner` at activation: each MMG op spawns one `node:worker_threads` Worker running `dist/mmgWorker.js` (its own esbuild entry next to the wasm; the worker injects the wasm itself), streams `{type:"progress"}` messages back, returns the structured-cloned `RemeshResult`, and is **terminated on `AbortSignal` abort** (→ rejects with `"cancelled"`) — this is what makes the providers' progress notifications live and cancellable, keeps the extension host unblocked, and releases MMG's grown WASM heap per run. Plain Node/tests keep the in-process default runner in `operations.ts`. Tests: `src/test/mmgWorker.test.ts` (round-trip + cancel via the compiled `out/` layout).
- `src/parser/removeOrphanNodes.ts` — pure `removeOrphanNodes(model)`: drops nodes referenced by no cell connectivity **and** listed in no SubModelPart, keeping original ids for survivors (connectivity untouched), shrinking Nodal fields, recomputing bounds. Returns `{model, removed}`. Reused by `deleteSubModelPart`. Tests: `src/test/removeOrphanNodes.test.ts`.
- `src/parser/mergeNodes.ts` — pure `mergeNodes(model, tolerance)`: welds nodes sharing a tolerance-sized coordinate grid cell (lowest id = representative), rewiring block connectivity / SubModelPart lists / Nodal fields (representative's record wins). Returns `{model, merged}`. Tests: `src/test/mergeNodes.test.ts`.
- `src/parser/transformCoords.ts` — pure coordinate transforms: `scaleCoords(model, sx,sy,sz)`, `translateCoords(model, dx,dy,dz)`, `rotateCoords(model, axis, angleDeg, cx?, cy?, cz?)` (right-handed, about a line parallel to a coordinate axis through the center point — defaults to the origin). Each maps every node + recomputes bounds. Tests: `src/test/transformCoords.test.ts`.
- `src/parser/deleteSubModelPart.ts` — pure `deleteSubModelPart(model, path)`: removes the part's (subtree) elements/conditions/geometries from blocks + their elemental/conditional fields, prunes the part from the tree, then runs `removeOrphanNodes`. Reuses `findSubModelPart` from `subModelPartExtract.ts`. Returns `{model, deleted}`. Tests: `src/test/deleteSubModelPart.test.ts`.
- `src/parser/linearToQuadratic.ts` — pure (no `vscode`/DOM/vtk) `linearToQuadratic(model)` transforms a linear mesh into a quadratic one by inserting mid-edge nodes (serendipity: Triangle2D3→Triangle2D6, Tetrahedra3D4→Tetrahedra3D10, Hex8→Hex20, Line2→Line3, …). Welds one new node per unique mesh edge (shared edges deduped via a `"lo:hi"` key) at the straight-edge midpoint, appends them to each cell's connectivity in the VTK/Kratos-canonical edge order (fresh edge tables — **not** reused from `planeCut.ts`, whose order is cut-only), rewrites each block's name/`vtkCellType`/`stride`, interpolates Nodal fields at mid nodes (average of both parents, only when both carry the field), and extends SubModelPart node lists with mid nodes of fully-enclosed edges. Cells with no quadratic counterpart (or already quadratic) are copied unchanged and listed in `skippedBlocks`. Returns `{ model, convertedCells, addedNodes, addedNodeIds, skippedBlocks }` (`addedNodeIds` drives the semitransparent mid-node overlay in the preview). Invoked as the `linearToQuadratic` op via `operations.ts`/`OperationHistory`. Unit tests: `src/test/linearToQuadratic.test.ts`.
- `src/parser/subModelPartExtract.ts` — pure (no `vscode`/DOM/vtk) `extractSubModelPart(model, path)` builds a standalone `MdpaModel` containing only the SubModelPart at `path` **plus its descendant subtree**: joins the part's (recursive) id-lists against `model.blocks` to slice matching entities, derives the referenced node set (connectivity closure ∪ the part's own nodes, keeping original ids — no renumbering), slices `fields` per kind, and re-roots the part as top-level so the output carries the grouping. `findSubModelPart(model, path)` is the depth-first lookup (paths use `/` separators). Feeds `writeMeshFile` unchanged. Unit tests: `src/test/subModelPartExtract.test.ts`.
- `mdpaEditorProvider.ts` — resolves custom editors for `.mdpa`: parses the document text, serves the webview HTML, and re-parses on change (debounced 250 ms). Tracks the active panel so window-level commands can reach it.
- `vtkEditorProvider.ts` — resolves custom editors for every mesh format (viewType id stays `kratos.vtkPreview`). All parsing goes through `parseMeshFile` from `meshFileParser.ts`. On `"ready"`: timeline-capable extensions (`TIMELINE_EXTENSIONS` from `meshFormats.ts` = `.vtk` + VTK XML + `.vtm`) list sibling files, call `groupVtkFiles(files, TIMELINE_EXTENSIONS)` to build a `VtkFileGroup` (timeline + subpart tree), send `"vtkGroup"` then `"vtkFrame"` for the initial step; static formats (`.stl`/`.obj`/`.ply`) skip grouping and load solo. On `"vtkRequestFrame"`, parses the requested step + merges subpart files via coordinate matching → sends `"vtkFrame"`. Watches the directory (glob built from `TIMELINE_EXTENSIONS`) so newly-written step files automatically extend the timeline; static formats create no watcher.
- `src/parser/mdpaParser.ts` — tolerant line-oriented state-machine. Uses a `stack: Frame[]` to handle nested `Begin`/`End` blocks. Merges repeated `Begin Elements <Name>` blocks into one `EntityBlock` so split files form a single layer. Parses `Begin NodalData`/`ElementalData`/`ConditionalData <VAR>` blocks into `FieldData` (scalar `id [is_fixed] value`, vector `id [N] (v1,…)`; flag-only nodal lines become value 1) while still recording the meta line-count. Emits non-fatal `MdpaDiagnostic` entries rather than throwing.
- `src/parser/geometryMap.ts` — maps Kratos type names (e.g. `Element2D3N`, `Triangle2D3`) to VTK cell type ids. Primary lookup: `(dimension, nodeCount)`; fallback: `(family-word, nodeCount)`. The table mirrors `kratos/input_output/vtk_definition.cpp`.
- `src/parser/types.ts` — the shared data model (`MdpaModel`, `EntityBlock`, `SubModelPart`, `FieldData`, etc.). Intentionally free of `vscode` and DOM imports so it can be used in both runtimes and in plain Node tests.
- `src/parser/meshQuality.ts` — pure (no `vscode`/DOM/vtk) geometric mesh-quality metrics inspired by Kratos' `ComputeMeshQualityProcess`: aspect/edge ratio, min/max angle (dihedral for volume cells, interior corner angles for surface cells), and per-node size gradation. Classifies every element into good/acceptable/bad/unacceptable bands (thresholds mirror the Kratos defaults) and returns per-metric histograms + the ids of bad elements. BC/flag-dependent checks (dead-tetra, gap/hole detection) are intentionally omitted — undefinable for a purely geometric mesh. Re-declares the small face tables locally rather than importing `meshBuilder` (which pulls in vtk.js) so it stays Node-testable. Unit tests: `src/test/meshQuality.test.ts`.
- `src/parser/isoSurface.ts` — pure (no `vscode`/DOM/vtk) scalar isosurface extraction (vtk.js has no unstructured-grid contour). Decomposes each volume cell into tetrahedra (tet→1, pyramid→2, wedge→3, hex→6) and runs sign-based marching tetrahedra; 2D / surface-only meshes fall back to marching triangles, yielding iso-lines (`is2D: true`). Crossing points weld across cells via an unordered node-id edge key. Returns plain typed arrays (`points`, `triangles`, `lines`). Unit tests: `src/test/isoSurface.test.ts`.
- `src/parser/meshFileParser.ts` — the format dispatcher: `parseMeshFile(fsPath, onProgress?)` routes by lowercased extension. `.vtk` sniffs the 3rd header line (`BINARY` → whole-buffer `parseVtkLegacyBinary`, else the streaming ASCII parser); VTK XML extensions → `parseVtkXml`; `.vtm` → `parseVtm` (with `parseMeshFile` injected for children); `.stl`/`.obj`/`.ply` → their parsers. `readFileWithProgress` keeps the loading bar working for buffer-based formats. Unit tests: `src/test/meshFileParser.test.ts`.
- `src/parser/meshFormats.ts` — pure extension constants: `VTK_XML_EXTENSIONS`, `TIMELINE_EXTENSIONS` (participate in step grouping), `STATIC_EXTENSIONS`, `SUPPORTED_MESH_EXTENSIONS`.
- `src/parser/writers/` — the **writer layer** (inverse of the parsers): serialises an `MdpaModel` back to file text for Save/Export. `writerCommon.ts` holds the shared helpers — `nodeIndexMap` (connectivity stores node **ids**, so index-based formats remap id→0-based), `buildCellLayout` (flattens all blocks into one ordered cell list + element/condition id→cell maps), `surfaceTriangles` (surface cells + volume **boundary** faces via a once-seen face map; `{ volumeOnly }` option), and `point/cellFieldArray` (positional field arrays). Per-format writers: `mdpaWriter.ts` (id-based; copies `Properties`/`ModelPartData`/`Table` blocks verbatim from the original source text when given `{ sourceText }`, else emits a default `Properties 0`), `vtkLegacyWriter.ts` (ASCII UNSTRUCTURED_GRID + FIELD data), `vtkXmlWriter.ts` (`writeVtu`/`writeVtp`, inline ASCII DataArrays), `stlWriter.ts`/`objWriter.ts`/`plyWriter.ts` (surface formats; volume cells → boundary triangles). `meshWriter.ts` is the dispatcher: `writeMeshFile(model, ext, opts?)`, and it re-exports the format registry from the dependency-free `exportFormats.ts` — `EXPORTABLE_EXTENSIONS` (`.mdpa/.vtk/.vtu/.vtp/.stl/.obj/.ply` — structured `.vti/.vts/.vtr` and `.vtm` are **excluded**, an unstructured model can't reconstruct them), `EXPORT_FORMAT_LABELS`, `isExportableExtension` (kept in their own module so the webview bundle can import the list without pulling in the writers). Pure/Node-testable; round-trip tests (`parse → write → re-parse`) in `src/test/writers.test.ts`.
- `src/parser/modelBuilder.ts` — shared model-assembly helpers used by every mesh parser: `buildBlocksFromOffsets(types, offsets, connectivity, diagnostics, startEntityId?)` groups VTU-style cells into `EntityBlock`s per `(cellType, stride)` (names `VtkCell_<type>`, extra strides `VtkCell_<type>_<stride>n`) and **normalizes undrawable cell types** (POLY_VERTEX→VERTEX, POLY_LINE→LINE segments, POLYGON→TRIANGLE/QUAD/fan, TRIANGLE_STRIP→triangles), returning a per-cell `expansion` array; `expandCellField(field, expansion)` re-aligns cell data after splitting; `fieldFromTuples` and `finalizeModel` (bounds/is3D/synthesised nodeIds). Unit tests: `src/test/modelBuilder.test.ts`.
- `src/parser/binaryTypes.ts` — the binary scalar-type table (`binaryType(name)`) shared by PLY, VTK XML, and binary legacy VTK; covers PLY (`uchar`…), VTK XML (`Float32`…), and legacy (`unsigned_char`…) spellings, incl. 64-bit ints via BigInt.
- `src/parser/vtkLegacyParser.ts` — pure (no `vscode`/DOM/vtk) parser for legacy VTK files (`DATASET UNSTRUCTURED_GRID`). Emits `MdpaModel` so the entire webview pipeline is reused unchanged. The streaming line parser handles ASCII (`FIELD FieldData N` primary path, `SCALARS`/`VECTORS`/`TENSORS` fallback; still bails with a diagnostic if fed BINARY text directly); `parseVtkLegacyBinary(buf)` walks the whole buffer for binary files (ASCII keyword lines + big-endian payloads) — the dispatcher decides which runs. Cell staging feeds `modelBuilder`; `subModelParts` is always `[]` from the parser — populated by `vtkEditorProvider` after coordinate-matching. Unit tests: `src/test/vtkLegacyParser.test.ts`.
- `src/parser/vtkXmlCore.ts` — buffer-aware VTK XML reader (raw appended data makes the file non-well-formed XML, so the buffer is split at `<AppendedData` byte-level first, then a small hand-rolled tokenizer parses the head; zero XML dependencies). `decodeDataArray` covers the full encoding matrix: ascii, inline base64 (uncompressed = header+payload encoded together; zlib-compressed = header block base64-encoded **separately** from the concatenated compressed blocks), and appended raw (byte offsets) / base64 (character offsets), with `header_type` UInt32/UInt64 and both byte orders. Unit tests: `src/test/vtkXmlCore.test.ts`.
- `src/parser/vtkXmlParser.ts` — `parseVtkXml(buf)` dispatches on the `VTKFile type` attr: UnstructuredGrid (connectivity/offsets/types), PolyData (Verts/Lines/Polys/Strips synthesized as POLY_* types and normalized by `modelBuilder`; CellData order verts→lines→polys→strips stays aligned via the expansion map), ImageData/StructuredGrid/RectilinearGrid (extent-based hex/quad/line cells; ImageData synthesizes points from Origin/Spacing, RectilinearGrid from tensor-product `<Coordinates>`). Multi-`<Piece>`-aware with node offsets. Structured extents are size-guarded (hard error >50M points, diagnostic >5M) **before** allocation. Unit tests: `src/test/vtkXmlParser.test.ts`.
- `src/parser/vtkMultiblock.ts` — `.vtm` support: `parseVtmIndex` walks the `<Block>/<DataSet>` tree (slash paths); `parseVtm(fsPath, parseChild)` merges the referenced files (child parser injected by the dispatcher to avoid a circular import) with node/entity-id offsetting, prefixes block names, emits one `SubModelPart` per DataSet, concatenates same-named fields, and **rejects paths escaping the .vtm directory** (diagnostic + skip). Fixtures: `src/test/fixtures/vtk/multiblock/`. Unit tests: `src/test/vtkMultiblock.test.ts`.
- `src/parser/stlParser.ts` / `objParser.ts` / `plyParser.ts` — surface-mesh parsers → `MdpaModel`. STL: ascii+binary with a byte-size cross-check (binary headers may start with "solid"); vertices welded via the 6-decimal coord key. OBJ: `v`/`f` (slash forms, negative indices, fans)/`l`/`p`, `g`/`o` groups → named blocks. PLY: ascii + binary LE/BE; extra numeric vertex properties become Nodal `FieldData`; `edge` elements become LINE cells. Unit tests: `src/test/{stlParser,objParser,plyParser}.test.ts`.
- `src/parser/vtkFileGroup.ts` — pure filename-grammar module. `groupVtkFiles(filenames, extensions = [".vtk"])` parses the Kratos naming pattern `<prefix>_<rank>_<step>.<ext>` (anchored from the right to tolerate underscores in part names), **bucketing by extension first** so mixed `.vtk`/`.vtu` series never cross-group, infers the parent/child prefix tree, and returns `VtkFileGroup[]` (now with `ext`) with `steps`, `ranks`, `subParts`, and a `fileMap`. `fileFor(group, prefix, rank, step)` looks up a filename; `findGroupForFile(groups, filename)` is extension-aware. Unit tests: `src/test/vtkFileGroup.test.ts`.
- `src/toolbarIcons.ts` — **generated** (never hand-edit). Exports `TOOLBAR_ICONS: Record<ToolbarIconId, string>`, the monochrome, theme-adaptive (`currentColor`-based) inline-SVG toolbar/panel icons. Pipeline lives in `icons/` and mirrors the sibling `CAD-Preview` project (same visual language; `wireframe`/`close`/`warning` are copied verbatim from it): `icons/tikz-ui/<id>.tex` → `pdflatex` + `pdftocairo -svg` → `icons/svg-ui/<id>.svg` → `icons/build-toolbar-icons.mjs` post-processes (strips width/height, black→`currentColor`, `gray!N`→`currentColor` + proportional `fill-opacity`) → this file. Regenerate with `npm run build:icons` (or `cd icons && make ts`); `svg-ui/*.svg` is committed so codegen alone needs no LaTeX. Consumed by both providers (an `icon(id)` helper wrapping each in `<span class="toolbar-icon">`) and by `webview/qualityPanel.ts` / `webview/fieldPanel.ts`. The `.toolbar-icon` CSS in `webview/style.css` sizes the SVG at `1em` with no color so it inherits the button's theme foreground. Invariants: `src/test/toolbarIcons.test.ts`. See `icons/README.md`.

### Webview (browser IIFE, `webview/`)
- `webview/main.ts` — entry point. Owns the VTK.js scene. On receiving a `model` or `vtkFrame` message it calls `buildScene(resetCam?)`, which creates one `vtkActor` layer per `EntityBlock` (visible) and one per `SubModelPart` (hidden by default). For `vtkFrame`, layer visibility is saved before rebuild and restored after (camera is also preserved by passing `resetCam=false`). Node-id labels are capped at 1 000 nodes. The `Quality` toolbar button / `computeQuality` message runs `computeMeshQuality` and toggles the quality panel; "Highlight bad" builds a red overlay layer (`quality:highlight`) from a metric's bad-element ids by reusing `addLayer`/`buildPolyData`. The `Field` toolbar button / `field` message toggles the field panel (see below). The `Find` toolbar button / `locateEntity` message opens a search bar: the matched entity is highlighted in yellow (`find:highlight` layer) and all other layers are forced to wireframe for contrast; closing the bar restores the prior wireframe state. The `📷` toolbar button calls `takeScreenshot()`, which uses `apiRW.captureNextImage()` (falling back to `canvas.toDataURL()`) and sends a `screenshot` message with the base64 PNG to the extension host. On `vtkGroup`, a `TimelineControl` bar is shown at the bottom of the viewport. Module-scope maps `elementById`, `conditionById`, `geometryById` are populated in `buildScene()` and shared by the quality panel, the find feature, and quiver cell-centroids.
- `webview/meshBuilder.ts` — converts `MdpaModel` nodes + `Cell[]` into `vtkPolyData`. Handles point clouds (no cell type) as vertex cells. Optionally takes a `FieldAttach`: nodal scalars are pushed into the point-data array *inside* `localOf` as each local point is born (so they stay aligned with the local remap), and cell scalars are collected per emitted cell in VTK's verts→lines→polys order — volume boundary faces inherit their owning cell's value via a face-owner map.
- `webview/outline.ts` — renders the sidebar tree of checkboxes (toggle layer visibility) and labels (frame/zoom to layer). SubModelPart rows (`exportPath` set) also get an export button that deploys a body-attached format dropdown (`OutlineExportUI` = icon + `EXPORTABLE_EXTENSIONS` from the pure `writers/exportFormats.ts`), posting `menuExportPart {format, path}` via the `onExport` handler, **plus a delete (X, `close` icon) button** that posts `applyOp {op:"deleteSubModelPart", path}` via `onDelete`; only one dropdown is open at a time (outside-click / Escape / scroll dismiss).
- `webview/qualityPanel.ts` — renders the `QualityReport` as a floating panel: verdict header + one card per metric with a min/mean/max line, a stacked band bar, and a canvas histogram. Pure DOM + Canvas 2D (no charting lib; the CSP forbids CDN scripts).
- Field visualization (toggled by the `Field` button) lives in five modules. `webview/fieldData.ts` turns a `FieldData` into id→value lookups + scalar/magnitude range (`buildFieldInfo`, `scalarAt`, `vectorAt`). `webview/colormaps.ts` is the colormap registry (Rainbow/jet default, Viridis, Cool-warm, Grayscale) as RGB stops feeding both the vtk `ColorTransferFunction` and the DOM legend gradient. `webview/fieldRender.ts` wires scalar coloring onto a mapper and builds isosurface polydata. `webview/quiver.ts` builds an arrow-glyph actor (`vtkGlyph3DMapper` + `vtkArrowSource`) oriented/scaled by the vector array and colored by magnitude. `webview/fieldPanel.ts` is the floating panel (variable + mode selectors, colormap dropdown + legend, iso-value / arrow-scale sliders). `main.ts` owns the `field:contour` / `field:quiver` / `field:iso` overlay layers and dims base layers to wireframe while a field is shown; the iso slider rebuilds via a `requestAnimationFrame` debounce.
- `webview/orientationCube.ts` — sets up a `vtkAnnotatedCubeActor` (Kratos face labels: RIGHT/LEFT/TOP/BOTTOM/FRONT/REAR) plus a `vtkAxesActor` (prominent X/Y/Z colored arrows with letter labels) inside a `vtkOrientationMarkerWidget` in the bottom-left corner. Always visible. A capture-phase `pointerdown` listener on the WebGL canvas intercepts clicks within the widget viewport, runs `vtkCellPicker` against the widget's own renderer, reads `getMapperNormal()` from the hit face, and snaps the main camera to that axis direction. Returns an `OrientationCubeHandle` with `updateTheme(theme)` so axis label colors adapt to light vs. dark themes.
- `webview/navControls.ts` — `NavControls` class that injects a `#nav-controls` DOM overlay into `#viewport`. Provides orbit (azimuth/elevation ±15°, with press-and-hold auto-repeat), 4-way pan (proportional step = 15% of frustum half-height), zoom in/out (dolly ×1.25/×0.8, with press-and-hold), Fit (resets camera to show all actors), and Center (re-centers focal point on `computeVisiblePropBounds()`). All operations are webview-local — no `postMessage` round-trips. Exposes `show()`, `hide()`, `setBottomOffset(px)` (shifts the panel up when the VTK timeline bar is visible), and `updateTheme()`. Exports pure helpers `computeRightVector` and `computePanStep` for unit testing.
- `webview/gridAxes.ts` — wraps `vtkCubeAxesActor` (with the OpenGL backend explicitly imported for registration). Exposes `setVisible`, `updateBounds`, and `updateTheme`. Updated by `buildScene()` whenever a new model loads; toggled by the `Grid` toolbar button. Axis/tick label colours adapt to dark vs. light/scientific themes via `setAxisTextStyle` / `setTickTextStyle`.
- `webview/fileMenu.ts` — `initFileMenu(postMessage)` wires the "File" (Home) dropdown: toggles `#file-menu-popup`, dismisses on outside-click/Escape, and posts `menuOpen`/`menuSave`/`menuSaveAs`/`menuExport` (with `data-format`) to the host. The markup is the shared `FILE_MENU_HTML` constant in `src/webviewChrome.ts` (built from `TOOLBAR_ICONS` + `EXPORTABLE_EXTENSIONS`), rendered top-left of `#viewport` by both providers; styled by `#file-menu*` in `webview/style.css`. Icons `open`/`save`/`saveAs`/`export`/`fileMenu` were added to the TikZ pipeline.
- `webview/meshMod.ts` — `initMeshMod(post)` wires the Mesh Modification sidebar section (markup in `src/webviewChrome.ts` SIDEBAR_HTML): the "Convert Linear → Quadratic" button (with the generated `quadratic` TikZ icon) posts `applyOp {op:"linearToQuadratic"}` to the host, which runs it through the operation history and re-renders. The new mid nodes come back via the `midNodes` field and `main.ts` renders them as the semitransparent `meshmod:midnodes` points overlay (a toggleable "Quadratic mid-nodes" outline row). Also owns the two MMG `edit-form` blocks (`remesh`/`levelset` icons): **Remesh (MMG)** — mode select (`factor`/`hsiz`/`optimize`; the value input relabels and disables per mode) + a nested collapsible **Advanced** sub-form (`.edit-subform`: hmin/hmax/hausd/hgrad/angle, module override, nosurf/noinsert/noswap/nomove checks) — and **Level-set split (MMG)** — nodal-field select + isovalue + surface-only. Both post `applyOp` with their params via **play-icon apply buttons** (`.edit-apply-mmg`) that flip to a **stop icon** while the run is live (clicking then posts `opCancel`); `setMeshModProgress(state)` (driven by the host's `opProgress` messages via `main.ts`) shows an **inline indeterminate loading bar + the latest MMG log line** (`.edit-progress`) under whichever form triggered the run. `setMeshModFields(fields)` (called by `main.ts` on every `model`/`vtkFrame`) repopulates the level-set field select and disables the form when the model has no nodal fields. Collapse/Enter behaviour is inherited from `initEditHistory`'s generic `.edit-form` wiring. Styled by `.sb-action`/`.edit-subform`/`.edit-check`/`.edit-progress*`/`.edit-apply-mmg` in `webview/style.css`.
- `webview/editHistory.ts` — `initEditHistory(post)` wires the Edit sidebar section (markup in `src/webviewChrome.ts` SIDEBAR_HTML): undo/redo/clear controls, the `removeOrphanNodes` button, the **interactive transform forms** (Merge tolerance, Scale x/y/z, Translate x/y/z, Rotate axis+angle+center — each is a **collapsible dropdown** whose title toggles its inputs; each Apply button reads its inputs and posts `applyOp` with the params; Enter in a field applies), and Save/Load recipe buttons (`saveOps`/`loadOps`). (Delete-SubModelPart is triggered from the outline tree's X button, not here.) `renderOpHistory(state)` (called by `main.ts` on the host's `opState` message) reflects the history into the section: enables/disables the controls and renders the applied-operations list — one clickable row per op (undone rows greyed), clicking a row posts `opRevertTo {index}` for a partial revert. Styled by `.edit-*` in `webview/style.css`.
- `webview/sidebarResize.ts` — `initSidebarResize()` wires the `#sidebar-resizer` drag handle (between the sidebar and `#viewport`, injected by both providers) to set the sidebar width (clamped 160–640 px). The viewport is a flex child that grows to fill the rest, and the existing `ResizeObserver` on the render root re-sizes the VTK canvas automatically. Styled by `#sidebar-resizer` in `webview/style.css`.
- `webview/timeline.ts` — `TimelineControl` class for VTK time-series playback. Dynamically injects `#timeline-bar` into `#viewport` when `show(total, steps)` is called (hidden when `total <= 1`). Exposes `update(frameIndex, stepLabel, total)` and `hide()`. Owns the play/pause interval (calling `onFrameRequest` each tick) and the scrub slider (debounced 80 ms). Used only for VTK previews; has no effect on MDPA views.

### Build outputs
| Path | Contents |
|---|---|
| `dist/extension.js` | Extension host bundle (CJS, Node 18 target) |
| `dist/mmgWorker.js` | MMG worker-thread bundle (own esbuild entry; spawned per MMG op by `mmgWorkerClient`) |
| `dist/mmg-core.wasm` | MMG WASM binary, copied from `@loumalouomega/mmg-wasm` by esbuild plugin (fed to `configureMmg` at activation) |
| `media/webview.js` | Webview bundle (IIFE, ES2021, browser) |
| `media/style.css` | Copied from `webview/style.css` by esbuild plugin |

`media/` is the only allowed `localResourceRoots` for the webview. The extension-host build **aliases `@loumalouomega/mmg-wasm` to its CJS entry** (`esbuild.js`): bundling the ESM entry breaks because its `import.meta.url`-based wasm lookup becomes `undefined` in a CJS bundle.

### Message protocol (extension host ↔ webview)

| Direction | `type` | Payload |
|---|---|---|
| host → webview | `model` | `{ model: MdpaModel, fileName: string, keepCamera?: boolean, midNodes?: number[] }` (`keepCamera`/`midNodes` set when an in-place Mesh Modification re-posts: preserve the camera and highlight the new mid nodes) |
| host → webview | `error` | `{ message: string }` |
| host → webview | `resetCamera` | — |
| host → webview | `toggleNodeIds` | — |
| host → webview | `computeQuality` | — (toggles the mesh-quality panel) |
| host → webview | `field` | — (toggles the field-visualization panel) |
| host → webview | `locateEntity` | `{ entityType: "Node"\|"Element"\|"Condition"\|"Geometry", entityId: number }` |
| host → webview | `vtkGroup` | `{ fileName, group: { modelPartName, steps: string[], subParts: string[], ranks: number[] } }` (VTK only — sent once after `ready`; shows/sizes the timeline bar) |
| host → webview | `vtkFrame` | `{ model: MdpaModel, frameIndex: number, stepLabel: string, totalFrames: number, midNodes?: number[] }` (VTK only — one parsed time step including merged SubModelParts; `midNodes` set when a Mesh Modification re-posts the current frame) |
| webview → host | `ready` | — (triggers initial parse) |
| webview → host | `setTheme` | `{ theme: string }` (persisted in globalState) |
| webview → host | `screenshot` | `{ data: string }` (base64 PNG data URL; host opens a Save dialog and writes the file) |
| webview → host | `vtkRequestFrame` | `{ frameIndex: number }` (VTK only — sent by timeline play/scrub/step; provider responds with `vtkFrame`) |
| webview → host | `menuOpen` | — (File menu → Open; host shows an open dialog and opens the pick in the matching preview) |
| webview → host | `menuSave` | — (File menu → Save; host re-serialises to the source format and overwrites it, with a one-time warning) |
| webview → host | `menuSaveAs` | — (File menu → Save As; host shows a save dialog in the source format) |
| webview → host | `menuExport` | `{ format: string }` (File menu → Export ▸; host shows a save dialog and writes the chosen format) |
| webview → host | `menuExportPart` | `{ format: string, path: string }` (sidebar SubModelPart export dropdown; host slices the part at `path` + its subtree and writes the chosen format) |
| webview → host | `applyOp` | `{ op: string, ...params }` (Edit / Mesh Modification sidebar + outline delete-X; params come from the sidebar forms, e.g. `mergeNodes{tolerance}`, `scale{sx,sy,sz}`, `translate{dx,dy,dz}`, `rotate{axis,angle}`, `deleteSubModelPart{path}`, `remesh{mode,factor|hsiz,…tuning}`, `levelset{variable,isovalue?,isosurf?}`. Host validates via `opRecordFromMessage`, `history.applyNew(rec)` (async, with an in-flight guard; MMG ops stream `opProgress` and honor `opCancel`), re-posts `model`/`vtkFrame` + `opState`. The edited model flows into Save/Export) |
| webview → host | `opCancel` | — (stop button on the running MMG form; host aborts the in-flight op's `AbortController` → the worker is terminated and the op resolves as a cancelled noop) |
| webview → host | `opUndo` / `opRedo` / `opClear` | — (mutate the operation history, re-post the current model + `opState`) |
| webview → host | `opRevertTo` | `{ index: number }` (partial revert — set the history cursor to `index` ops applied) |
| webview → host | `saveOps` / `loadOps` | — (save the applied ops to / load+replay a JSON recipe; host shows a save/open dialog) |
| host → webview | `opState` | `{ ops: {op,label}[], cursor: number, canUndo: boolean, canRedo: boolean }` (drives the Edit-section history list + control enablement) |
| host → webview | `opProgress` | `{ running: boolean, op?: string, message?: string }` (streamed during an MMG op — `meshMod.setMeshModProgress` shows the inline loading bar + latest log line under the triggering form and flips its play button to a stop/cancel button; `running:false` hides it) |

### Packaging & CI
- `.github/workflows/package.yml` builds a `.vsix` on every `v*` tag push and creates a GitHub Release with it attached. Uses `./node_modules/.bin/vsce` (not `npx vsce`) to ensure the `@vscode/vsce` version from `devDependencies` is used.
- `vscode:prepublish` runs the production esbuild before `vsce package`.
- `.github/workflows/ci.yml` runs `npm run typecheck` + `npm test` on every push to `master` and on PRs.
